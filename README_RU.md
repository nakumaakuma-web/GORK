# Prompt Extractor Studio v0.7 — режиссёр анимации и FramePack

**Канал:** [nakumaakuma-web/GORK](https://github.com/nakumaakuma-web/GORK)  
**Манифест:** https://raw.githubusercontent.com/nakumaakuma-web/GORK/main/update-manifest.json

## Назначение
Локальный анализ изображений и видеокадров с помощью Qwen3.5 через `llama.cpp` на `127.0.0.1:8080`.
Результат: отдельные Positive/Negative RU/EN, внешность, поза, одежда, освещение, заготовки движения для FramePack.
Исходные негативные промпты по изображениям восстановить нельзя: приложение создаёт новые.

## Обновления
Программа проверяет канал версии при запуске и по кнопке «Проверить обновления».
По кнопке «Установить обновление» она скачивает только исходники приложения из GitHub,
проверяет размер и SHA-256, делает резервную копию, откатывает частичную установку при сбое.
Модели GGUF, пользовательские файлы, результаты анализов, локальный `update_config.json` не заменяются.

**Как подключить установленную v0.2:** единственный раз запустить скрипт `connect-updates.cmd` двойным щелчком в Windows
(или записать `manifest_url` из опубликованного `update_config.json` в локальный конфиг).
Затем в v0.2 нажать «Проверить обновления» → «Установить обновление».
После обновления проверка GitHub будет работать без ручных ZIP.

> Проверка SHA-256 удостоверяет соответствие байтов манифесту, но не является цифровой подписью автора. Доступ к репозиторию должен быть защищён. Автоматическое применение без нажатия кнопки не включено.

## Особенности и ограничения
- Qwen на 8 ГБ VRAM может обрабатывать изображения медленно.
- Анализ видео строится по ключевым кадрам, аудио отдельно не анализируется.
- Состояние FramePack не меняется, видео не генерируется в Prompt Extractor Studio автоматически.
- Полное восстановление оригинального промпта по готовому изображению невозможно.
- Сравнение качества на реальных файлах и контроль сторон тела необходимы.

## Запуск
`start-all.cmd` запускает Qwen из известных путей при необходимости и затем UI `http://127.0.0.1:8765`.
`start-studio.cmd` запускает только UI.
Требуется Python 3.10+. Дополнительные Python-библиотеки не нужны.

## Для разработчиков
`py -3 -m unittest discover -s tests -v`
Подтверждённая версия: `0.5.0`.

## Изменения v0.4
- В максимальном режиме три тематических прохода, затем четвёртая визуальная сверка по ИСХОДНОМУ изображению, затем сборка промптов.
- Отдельная вкладка «Анатомия» и «Проверка качества».
- Стороны тела фиксируются относительно персонажа; при сомнении указана неопределённость.
- Формальная диагностика RU/EN сообщает о возможных противоречиях в сторонах тела и переводе чулок/материалов (не исправляет без проверки).
- Взрослый визуальный материал анализируется объективно, только видимые признаки; оригинальные негативные промпты не восстанавливаются.
- Видео всё ещё анализируется по выбранным кадрам и не восстанавливает промежуточные движения.

Качество нужно проверять на отдельных фотографиях до применения для создания контента.

## Исправление v0.4.1
Добавлена программная проверка языка каждого из четырёх промптов. Если Qwen пишет на английском в Positive RU или Negative RU (либо на русском в полях EN), Studio автоматически запускает адресный запрос перевода нужного поля и повторно проверяет язык. При повторной ошибке поле очищается и ошибка отображается в отчёте качества вместо ложного русского результата. Визуальная точность по-прежнему требует сверки с исходником.


## Изменения v0.5.0 (основа стабильности и ускорения)
- Единая версия из updater.VERSION в интерфейсе и API; устранено повторное предложение уже установленной версии.
- Один активный GPU-анализ одновременно, чтобы не перегружать RTX 3060 Ti.
- Три режима: быстрый (2 запроса), сбалансированный (3), максимальный (5), без учёта дополнительных исправлений языка.
- Кнопка «Остановить»: прерывает цепочку **после** текущего ответа Qwen; уже выполняемый запрос llama.cpp не прерывает.
- Показывает предварительные результаты каждого прохода до окончательного промпта.
- Кэш повторного анализа в RAM (до 5 результатов), без записи исходных изображений и промптов на диск. Кэш пропадёт после перезапуска.
- API /api/version показывает фактическую установленную версию.
- Дальше запланированы структурированный визуальный паспорт, выборочные уточнения, ROI/коллажи и более точный видеопромпт.

- Неправильные стороны тела, ткани или «soft lighting / soft focus» между RU/EN вызывают **выборочную** попытку перевести только EN с RU; после этого повторная диагностика.
- Появился машиночитаемый «Визуальный паспорт JSON»: внешность, анатомия, поза, одежда, стиль, неопределённости, упоминания сторон. Не заявляется как независимое доказательство точности.

## Изменения v0.5.1 — информативный монитор анализа

- Увеличена строка «Анализ кадров …»: шрифт 17px, перенос строк, отдельная панель текущего этапа.
- Показаны номера и диапазоны анализируемых кадров, последние 5 этапов, общее время и время текущего запроса к Qwen.
- Добавлена анимированная полоска ожидания; **это не процент готовности Qwen**. `llama.cpp` возвращает итог этапа только после завершения запроса.
- Все данные о состоянии отражают реальные события от локального сервера или локальное извлечение кадров, а не имитацию ответа модели.
- После завершения или остановки показывает корректный статус; текущий анализ не прерывается установкой новой версии (обновлять после его окончания).

## Исправление v0.5.2 — обязательные видеополя
После основного текстового анализа программа проверяет, что FramePack RU, FramePack EN и Timeline RU действительно заполнены.
Если Qwen не вернула один из разделов, выполняется отдельный текстовый запрос без повторного анализа кадров; при необходимости — адресный запрос для отдельного поля.
Если восстановить поле всё же не удалось, оно честно остаётся пустым, а в отчёте качества появляется ошибка.
Кнопка «Восстановить FramePack / Хронологию» позволяет использовать уже готовый текстовый анализ.
Чтобы воспользоваться прежним результатом после обновления, сначала сохраните JSON, потом загрузите его через «Открыть JSON» и нажмите восстановление.
Таймлайн строится только на известных временных метках и наблюдаемых изменениях, без выдуманных промежуточных кадров.


## v0.6 — временной анализ видео для FramePack

- Режим «8 ключевых кадров — адаптивно»: браузер сравнивает 18 равномерных кандидатов в низком разрешении, выбирает 8 по заметным различиям с распределением по длительности и отправляет только их Qwen. Это эвристика по изменению пикселей: **не** оптический поток, не анализ всех кадров и не доказательство движения.
- Любой выбор (3, 5, 8, адаптивный 8) показывает временные миниатюры. Нажатие на миниатюру перемещает видеоплеер к указанному моменту.
- По каждому выбранному кадру Qwen получает точное время и обязана отдельно описать видимую позу/композицию и изменения относительно соседнего выбранного кадра.
- FramePack RU, FramePack EN и Timeline RU теперь создаются отдельным текстовым проходом ПОСЛЕ основного анализа; они не зависят от того, хватило ли токенов на общий ответ.
- Отчёт предупреждает, какие временные метки пропущены. Никаких придуманных поз между выборками: монтаж и непрерывное движение камеры не могут быть подтверждены редкой выборкой.
- Существующие кнопки восстановления из JSON остаются совместимыми с прежними версиями. Пользовательские файлы, GGUF и FramePack не меняются.

**Ограничение:** тесты выполнены на синтетических данных и заглушке Qwen. Реальную точность на видеороликах надо проверять по выбранным кадрам.


## v0.7.0 — режиссёр анимации Anime / 2.5D / Realism

Реализована секция «03 / Режиссёр анимации» прямо в интерфейсе Prompt Extractor Studio.
Она работает отдельно от анализа исходного видео и не требует повторять долгий анализ Qwen, если есть готовый визуальный паспорт.

**Промпты:**
- Три профиля рисовки: Anime/2D (стабильные контуры, глаза и cel-shading), Semi-Real/2.5D (рисованная фактура и узнаваемость), Realistic (анатомия, свет, естественное движение).
- Управление камерой: статичная, плавное приближение, панорама или сопровождение.
- Темп: спокойный, естественный, динамичный.
- До пяти **временных этапов** с действиями на русском языке; строгая проверка времён, отсутствия наложений, длительности 2–15 с.
- Кнопка «Взять внешность из анализа» переносит данные из уже созданных разделов.
- Qwen переводит и редактирует режиссёрские указания в FramePack EN, одновременно создаёт Motion RU. При наличии собственного EN можно не запускать Qwen.
- Промпты и хронология доступны для копирования, TXT и редактируемого JSON-проекта (с открытием сохранённого JSON).
- Режим сцен 18+ доступен только для взрослых персонажей; требует подтверждения совершеннолетия. Возраст нельзя надёжно определить по одному изображению.

**Отправка в локальный FramePack F1 (экспериментальная интеграция):**
- Введи локальный адрес FramePack (например, http://127.0.0.1:7860), нажми «Проверить связь».
- Для запуска нужен исходный кадр. При выборе видео можно использовать текущий кадр видеоплеера.
- Поддерживается проверенная структура **официального** `demo_gradio_f1.py` (13 входных параметров, 6 выходных). При несовместимости API программа выдаёт ошибку, не пытаясь запустить неизвестную функцию.
- Отправляется подготовленный кадр, Motion Prompt EN, длительность, seed и TeaCache; ход выполнения читается из событий Gradio, готовый MP4 сохраняется локально в `outputs/`, с предпросмотром и загрузкой.
- **Не подтверждено с конкретной установкой пользователя:** автоматические проверки использовали имитацию Gradio; реальный запуск и корректность ролика должны быть проверены на уже установленном FramePack.
- Уточнение: в официальном FramePack F1 поле Negative Prompt скрыто и помечено `Not used`; не обещаем влияния Negative EN на выходное видео. Контроль внешности и стабильности включён в положительный motion prompt.
- На 8 ГБ VRAM одновременная загрузка Qwen и FramePack может привести к нехватке памяти. Для рендера освободи GPU при необходимости.

**Обновления:** исправлена устаревающая проверка GitHub: динамический параметр `pes_check` и заголовки без кэша. GGUF, FramePack и результаты пользователя не заменяются. Текущие файлы в `outputs/` также не затрагиваются.

## Отдельно о точности

Наличие готового prompt и даже корректной отправки API не гарантирует физически правильную анимацию. Длинные сцены и сложное взаимодействие объектов требуют дополнительной проверки полученного MP4; FramePack остаётся генеративной моделью. Временные этапы — инструкция, не гарантия покадрового исполнения.
